# TUBITAK JNLP Guard for macOS

[Türkçe](README.md)

A narrowly scoped helper that prevents macOS from repeatedly requiring **Open Anyway** for the new `.jnlp` file generated by the TÜBİTAK e-signature service for every signing job.

> [!WARNING]
> This project is not affiliated with or endorsed by TÜBİTAK. JNLP files can run Java code with broad system permissions. Use this tool only if you understand that risk.

## Why is this needed?

Chrome and other browsers add the `com.apple.quarantine` attribute to downloaded JNLP files. TÜBİTAK generates a differently named file for each signing job, so macOS does not apply a previous **Open Anyway** decision to the next file.

This tool does not disable Gatekeeper. It watches Downloads and removes quarantine only when every check below passes:

- The item is a regular `.jnlp` file, not a symbolic link.
- The first URL in the real `kMDItemWhereFroms` metadata uses HTTPS and has the exact host `e-imza.tubitak.gov.tr`.
- The JNLP codebase is under `https://e-imza.tubitak.gov.tr/sublimity-ess/jnlp/`.
- Every JAR reference in the JNLP resolves to the same trusted HTTPS host.
- The file is smaller than 1 MiB and parses as valid XML.

The tool does not open the file automatically and does not remove any other extended attribute.

## Install

Requirements: macOS 13 or later and Xcode Command Line Tools.

```zsh
git clone https://github.com/kadirseker00/tubitak-jnlp-macos-helper.git
cd tubitak-jnlp-macos-helper
./scripts/install.sh
```

macOS asks for access to Downloads during installation. Choose **Allow**. No `sudo` is required.

After installation, download the JNLP from TÜBİTAK, wait about 1-2 seconds, and open it normally.

## Uninstall

```zsh
./scripts/uninstall.sh
```

The uninstaller removes the LaunchAgent, local app, log, and Downloads permission.

## How it works

The installer builds the source locally and creates a small ad-hoc-signed macOS app. A per-user LaunchAgent starts the app when Downloads changes. The app performs the validation checks and removes only `com.apple.quarantine` from matching files.

Installed components:

```text
~/Library/Application Support/TubitakJnlpGuard/TUBITAK JNLP Guard.app
~/Library/LaunchAgents/org.kadirseker.TubitakJnlpGuard.plist
~/Library/Logs/TubitakJnlpGuard.log
```

## Security boundary

This tool cannot prove that Java code served by TÜBİTAK is safe. It verifies only that the file came from the expected HTTPS origin and does not redirect to an external JAR. It cannot protect you if the TÜBİTAK domain or server is compromised.

It deliberately avoids broad workarounds such as:

```zsh
sudo spctl --global-disable
xattr -cr ~/Downloads
```

## Development

```zsh
swift test
./scripts/build-app.sh
```

The tests cover trusted files, lookalike domains, external JAR references, unexpected codebase paths, and symbolic links.

## Privacy

The helper makes no network requests and collects no telemetry. Its log contains numeric scan summaries only; it does not log filenames or JNLP job identifiers.
